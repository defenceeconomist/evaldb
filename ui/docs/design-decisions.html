Table and detail pages

The landing page is a table with record ID, report title, country, report date, evidence type, business case and decision use. A left sidebar provides business case, topic, evidence type, country and source-access filters, alongside search and sorting. Filters combine and persist in the URL when opening a detail page and returning. Map these dropdowns to Power BI slicers. Selecting a title opens its detail page. Shortlists and browser-local storage have been removed.

Use Segoe UI, neutral backgrounds, grey column headers and blue links. Report dates use the original ISO-style values; preserve their precision when importing rather than assuming every record has a complete date.

Create a drill-through detail page filtered by evaluation_id. Show title, country, report date and evidence type at the top, then business-case use, MOD relevance, evidence limits, question, methods, findings, recommendations, conclusions and transferable lesson. Keep source links and evidence locators visible. A Back button returns to the table. Native Power BI drill-through can be exposed through a button or context menu; title-click navigation in this site is a browser convenience.

Data imports

Import evaluation_summaries.csv as the main table. Each export has one row per record and the same 28 record IDs. Columns use stable field names. Multi-value topics and business_case_uses use semicolon separators; split them into related tables in Power Query if slicers are required. The criteria_results column is a flattened screening description. Source URL columns can use Power BI’s Web URL data category. Do not join the three exports into duplicate fact rows: sources and review exports are alternative views of the same records.

No shortlist state, custom visual, pop-up, hover-dependent content or browser storage is required. Narrative fields remain on the detail page rather than in the table. Power BI is the target for a future rebuild; this site remains a static HTML implementation.
